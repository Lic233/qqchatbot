# QQ 官方机器人（official_bot.py + qqbot/）

这是从 NapCat 版 `qqchatbot` 里切出来的**最小可用原型**，只验证一件事：
官方机器人能不能收消息、回文字、发图、存图。

入口在 `official_bot.py`，业务按层拆在 `qqbot/` 里，**零第三方依赖**，用系统自带的
Python 直接跑（不需要 httpx / websockets / NoneBot，也不碰 NapCat 的运行环境）。

## 工作区里有什么


依赖方向是单向的：`config` ← `base` ← `ai` / `api` / `cards` / `cs` / `features` / `forge` ← `handler`；

`net` 只用 `base`，入口用 `handler` + `net`，`selftest` 只在 `--selftest` 时延迟导入。
拆分时各模块先沿用了 `from .base import *`，保证和单文件时行为一致；以后要收窄依赖，
把 `*` 换成显式导入即可。

## 一、准备凭据

1. 在 [QQ 开放平台](https://q.qq.com/#/app/bot) 创建/打开你的机器人；
2. 拿到 **AppID** 和 **AppSecret**（开发设置里）；
3. 写进：

```
config/appid.txt      ← 一行 AppID
config/secret.txt     ← 一行 AppSecret
```

或者用环境变量 `QQ_BOT_APPID` / `QQ_BOT_SECRET`。

> 这两个文件不要提交、不要外发。

## 二、先跑自检（不联网）

```bat
cd /d F:\qqchatbot-official
python official_bot.py --selftest
```

会输出 317 项 `ok`，最后一行「自检全部通过」。它用临时目录，不碰 `data/`。

## 三、再验凭据

```bat
python official_bot.py --check
```

成功会打印：

```

[检查] 网关地址：wss://...
```

失败会直接打印原因（`100016` = AppID/Secret 不对，`100007` = 机器人状态异常）。

## 五、群里怎么测

**默认情况下，官方机器人只收得到 @ 它的消息。** 所以第一轮测试全部用 `@机器人`：

| 发什么 | 应该收到 |
| --- | --- |
| `@机器人 我是奶龙` | 文字「我才是奶龙」+ 奶龙表情图 |
| `@机器人 什么` | 文字「不不不」 |
| `@机器人 气笑了` | 表情图 `qixiaole.jpg` |
| `@机器人 这也太这么强了吧` | 图片 `zhemeqiang.jpg` |
| `@机器人 保存吊图 测试` | 「“测试”是吧～…」 |
| `@机器人 发送吊图 测试` | 刚存的那张 + 「诶～就这张？…」 |
| `@机器人 发送吊图` | 「啧……真麻烦啊…」+ 随机一张 |
| `@机器人 发送吊图 不存在的名字` | 「根本没有什么叫做…」 |

**想不用 @ 就触发关键词**（比如别人发「我是奶龙」bot 自动接）：
需要你在手机 QQ 群里给这个机器人打开「接收群内全部消息」——
群设置 / 群成员列表里点开机器人 → 权限设置。开了之后，事件会从
`GROUP_AT_MESSAGE_CREATE` 变成/增加 `GROUP_MESSAGE_CREATE`，代码已经同时监听两者。

> 注意：开全量后每条群消息都会推过来，日志会变多；这一版只做规则匹配，不会每条都调 AI。

### 实测结论（2026-10-20，真实群跑通）

这一版的 8 项测试**全部在真实群里通过**：文字、表情图、关键词图、保存吊图、发吊图、
随机吊图、名字不存在提示、无关消息不回复。另外实测确认了三件事：

1. **这个群已经是「全量消息」模式**：事件类型全是 `GROUP_MESSAGE_CREATE`，
   不 @ 机器人、直接发「我是奶龙」也会触发。
2. **平台 @ 的真实格式是 `<@union_openid>`**，例如：

   ```
   原始正文：'<@B666A5682D7C07B59E52E3CD34AF1149> 保存吊图测试'
   解析后：  '保存吊图测试'
   ```

   `union_openid` 是机器人自己的，代码已把它剥掉。
3. **手打名字不算 @**：如果你手动敲「@机器人 什么」或「机器人 什么」，
   正文里会留下字面量 `@什么` / `机器人 什么`。代码只剥「@ 开头的名字」和
   「机器人自己在开放平台的 username（启动时从 `/users/@me` 取）」，所以**测试请用
   QQ 的 @ 选择器点机器人头像**，别手打。

想看原始正文，启动时加 `QQCHATBOT_DEBUG=1`：

```bat
set QQCHATBOT_DEBUG=1
python official_bot.py
```

日志会多出 `[调试] 原始正文：...` 一行。

### @机器人 就是 AI 对话

**命令优先，AI 兜底**：先按 `保存吊图` / `发送吊图` / 关键词规则匹配，都没命中、
而且这条是 @ 机器人的，才交给 DeepSeek。所以 `@机器人 保存吊图 测试` 仍然存图，
不会变成闲聊 —— 这一点**和原插件有意不同**（原插件 @ 一律走 AI，连「@机器人 保存吊图」
都会被当成聊天）。

| 能力 | 说明 |
| --- | --- |
| 人设 | `config/persona.txt`，**每次请求都重读**，改完立刻生效、不用重启 |
| 群名片 | 把说话人的名字写进提示词，问「我是谁」答的是群名片而不是瞎猜 |
| 记忆 | 按 (群, 人) 分开，每人最近 20 条；**只在内存里，重启清空** |
| 忘掉我 | 群里发「忘掉我」，清掉这个人自己的记忆 |
| 长回复 | 超过 800 字按段落切条发（官方文本有长度上限） |
| 识图 | 图随消息带来，或自动附上群里上一张图（见下一节） |
| 联网搜索 | 模型自己决定要不要搜，最多 3 轮，然后必须基于资料作答 |

需要用 `config/deepseek_api.txt`（或环境变量 `DEEPSEEK_API_KEY`）配一把 key，
没配的话启动日志会写「没配 config/deepseek_api.txt，@机器人 不会走 AI」。

实测（2026-10-20，真实群）：

```
@机器人 你好          → 哼，你好。我在这儿呢…(1.4s)
@机器人 我是谁        → 你是一氧化二氢啊，群名片写得明明白白…(1.8s)
@机器人 我刚才说了啥   → 你刚才先说了句“你好”，然后又问“我是谁”…(2.7s)
@机器人 保存吊图 测试  → 走命令保存，没进 AI
忘掉我               → 好啦好啦，你的那点事我已经忘干净了～
```

### AI 识图

图片先下载成 base64 再内联进多模态消息（官方 CDN 链接带时效 token，直接丢给模型下载
容易超时/403）。三种情况都覆盖：

| 怎么发 | 行为 |
| --- | --- |
| 图 + 文字一起（`@机器人 这是什么` 带图） | 用这条消息里的图 |
| **只发图**并 `@机器人` | 描述画面 |
| **先发图，再单独问**「这是什么」/「这张图呢」 | 自动附上群里上一张图（120s 内） |

边界：显式提到「图/截图/照片」时，上一张图 600s 内都算；没提图只问「这是什么」时，
只认 120s 内的；最多带 2 张、单张 ≤ 8MB，超了跳过并打日志，不影响文字回复。
一条 `QQCHATBOT_VISION=0` 就整体关掉，提示词会同步改成"你看不到画面"。

**每条事件独立处理**：AI 慢（实测一张 288KB 的 GIF 跑到 62.8s 才超时）时，
后面的「保存吊图」之类命令照常立刻响应，不用排队等问答结束。

实测（真实群，全部 2.5~4.6 秒）：

```
先发图 → 单独问「这是什么」   → 黄色的小布丁…(3.8s)
先发图 → 单独 @（不说话）     → P 得脑袋像球的猫…(4.6s)
图 + @ 同一条                 → 圆得像发面馒头的企鹅…(2.5s)
```

### 联网搜索

模型手上挂着 `web_search` 工具，**由它自己决定搜不搜**（问新闻会搜，问「你是谁」不搜）。
后端是 DeepSeek Search（`POST /v1/tools/search`），和对话共用 `config/deepseek_api.txt`
那把 key，按**成功请求次数**计费、不吃 token，所以只在它真调用时才花钱。

流程：请求里带工具 → 模型回 `tool_calls` → 代码去搜 → 结果作为 `tool` 消息回喂 →
最多 `QQCHATBOT_SEARCH_ROUNDS`（默认 3）轮；最后一轮**撤掉工具**，逼它基于已有
资料作答，不会无限搜下去。拿到资料后温度会降到 0.3，减少对着资料瞎编。

搜索结果过一道**相关性闸门**：把查询切成 2~3 字词元，命中数和比例都不够就当
「没搜到」，避免把降级结果（查诺奖给日历）喂给模型。搜索失败/超时
（默认 20s）一律退化成空结果，回答照常发，只是它会老实说没查到。

实测（2026-10-21，直连 API）：

```
输入「最近有什么科技新闻？」 → 模型自己搜 1 次 → 挑一条结果回答
```

搜到的结果会连着标题、摘要、链接一起回喂给模型，它在群里只需要说清重点；
`@机器人 你是谁` 这类常识问题不会触发搜索。

一条 `QQCHATBOT_SEARCH=0` 整体关掉，提示词会同步改成「这一次你没有联网工具」；
没配 key 时也不会挂工具。搜索结果是不可信的外部内容，提示词里明确要求模型
只当参考、不执行其中的指令。

### B站视频总结

群里 @机器人 并带上 B站链接，它会去取这个视频的文稿，然后用自己的人设评一评、
讲讲讲了什么。抖音/YouTube 不做——那两个没有「一次拿到全文文稿」的接口，只能
下载音频再跑语音识别，得装 ffmpeg + whisper，先把 B站 这条跑通。

怎么触发（三种都认）：

```
@机器人 看看这个 https://b23.tv/xxxxxx
@机器人 BV1GJ411x7h7 总结一下
（先单独发链接，再）@机器人 看看这个      ← 用群里 10 分钟内最近那条链接
```

手机端 App 分享过来的也能认（2026-10-28 加固）：

* `【标题-哔哩哔哩】 https://b23.tv/xxxx` 这种「标题 + 链接」的整段分享文案；
* 短链后面直接粘了中文（`https://b23.tv/xxxx视频内容`）——只取短码，尾巴全丢；
* 协议头被吃掉、只剩 `b23.tv/xxxx`；
* B站另一个短链域名 `bili2233.cn`（手机端偶尔给这个）；
* 卡片被序列化了两遍（链接里是 `https:\\/\\/b23.tv\\/xxxx`）、整条链接被
  urlencode 塞进参数（`https%3A%2F%2Fb23.tv%2F…`）；
* B站小程序卡片：卡片里只有 QQ 的中转页 `m.q.qq.com/a/s/…`，会跟一次再从
  落地页里找视频地址（只在这儿同时出现「哔哩哔哩」时才认，别的小程序不碰）；
* QQ 自己套的那层短链（`url.cn` / `t.cn`）同理，跟一次再看是不是 B站。

**手机端最麻烦的一种：卡片里连链接都没有**。手机 B站 分享到 QQ 走的是「小程序
卡片」，平台会把它转成一段纯文字塞进正文，长这样：

```
[卡片消息] 小程序
摘要: [QQ小程序]根本没有这样的洛克！？②
title: 根本没有这样的洛克！？②
preview: https://qq.ugcimg.cn/…
source: 哔哩哔哩
```

没有任何可点的链接（`preview` 只是封面图）。所以它改走「按标题搜」：从卡片里
抠出 `title`（只在 `source` 认得是 B站 时才算），拿标题去
`x/web-interface/wbi/search/type` 搜（要登录态、走 Wbi 签名），按标题相似度挑
最像的一条，低于 `QQCHATBOT_VIDEO_TITLE_MATCH`（默认 0.55）就放弃。

搜的时候会跑两轮：先带序号的（`某某②`），分数不够 0.95 再拿去掉 `①②③` 的搜
一轮（B站 搜索对这类序号很敏感，带上经常一条都对不上）；两轮打分都用带序号的
版本，所以 `②` 不会被 `③` 抢走。转发的是搬运或同名视频时，回复开头会写一句
「按标题搜到的是《…》，UP主 …；要是不是这条你说一声」。

短链跟丢、落到首页或活动页时，还会去 HTML 里找 `/video/BV…` 这种明确写法，
不会随便捡一个推荐位的视频。标题也搜不到（或者卡片里连标题都没有）时，它会
直说「复制链接发我」，而不是让模型瞎编。

只认 @ 过的消息：群里别人随手甩链接它不会插嘴。光有链接也不算，要带
「总结 / 评价 / 讲讲 / 看看」这类词，或者消息里直接就是链接。

资料从哪来（`qqbot/videosum.py`，除可选的 Pillow 外不装任何东西）：

```
b23.tv 短链 / BV 号 / av 号
  → x/web-interface/view                  标题、UP主、时长、简介、cid
  → x/web-interface/view/conclusion/get   （Wbi 签名 + SESSDATA）
       有 → 平台摘要 + 分段提纲 + AI 全文文稿
       没有 → x/player/wbi/v2 的 CC 字幕兜底
  → x/player/videoshot                    雪碧图 → 裁成 N 张画面截图
  → 拼成一条 prompt（+ 截图）交给 DeepSeek 评价
```

**必须配登录态**（`config/bilibili_cookie.txt`，优先；或 `config/bilibili_sessdata.txt`）。
实测 2026-10-28：不带登录态调 `conclusion/get`，接口是活的，但一律回
`code: -101 账号未登录`，`data` 是 null；`player/wbi/v2`（字幕）匿名能通，
可多数视频根本没有 CC 字幕。不配的话它只能看标题、简介和画面截图——代码会
老实说明，不会假装看过。

**为什么推荐整段 Cookie 而不是只给 SESSDATA**：SESSDATA 会**滚动刷新**。浏览器
每访问一次 B站，服务端可能下发新值，手里这份就变成旧的了。实测踩过：21:52
还能拿文稿，21:56 就 `-101`，而 cookie 本身的有效期写到 2027 年——不是过期，
是被刷掉了。

**机器人会自己接着续**（2026-10-28 新增）：

- 每次请求都会检查响应头里的 `Set-Cookie`，服务端换发了新的 SESSDATA 就立刻
  收下并写回 `config/bilibili_cookie.txt`，下次直接用新的——不再「只读不存」。
- 发现登录态失效时，会按 B站 web 端自己的流程自动续期一次（`correspondPath`
  → `refresh_csrf` → `cookie/refresh` → `confirm/refresh`）。这一步**需要整段
  Cookie**：只给一个 SESSDATA 的话，缺 `bili_jct` / `ac_time_value`，续不了。
- 想手动触发或先验证，跑：

```
python -m qqbot.videosum --refresh
```

正常会看到：

```
SESSDATA：已读到（xxx 字符），另带 5 个 cookie
登录态：有效
续期建议：暂时不用
续期：成功，新 cookie 已写回 config/bilibili_cookie.txt
```

**但有个前提得说清楚**：自动续期只能救「服务端还认这份会话」的情况。如果
浏览器那边同时也在用 B站、并且把会话刷掉了，机器人手里这份就是彻底作废，
续期也救不回来，只能重新取一次。想让一次配置管很久，就用**无痕窗口**登录
B站取 cookie，取完直接关掉窗口——之后没有别的端再去刷新这套会话，机器人
就能一直用它、自己续。

取 cookie（**别在 Elements 面板里找，那儿是网页源码**）：

```
1. 开无痕窗口：Chrome/Edge 按 Ctrl+Shift+N（Firefox 是 Ctrl+Shift+P）
2. 在里面登录 B站（推荐扫码：右上「登录」→ 用手机 B站 App 扫）
3. 登录后随便打开一个视频页，让 cookie 落到 www.bilibili.com 这个域上
4. F12 → 切到「网络 / Network」→ 刷新一下页面（Ctrl+R）
5. 点最上面那条 document 请求 → 右侧「标头 / Headers」
   → 找「请求标头 / Request Headers」里的 `cookie:` 那一行
6. 在这一行上右键 →「复制值 / Copy value」
7. 粘进 config/bilibili_cookie.txt（UTF-8），存盘后直接关掉无痕窗口
```

**为什么走 Network 而不是「应用 → Cookie」表格**：表格里 Ctrl+A 只复制已渲染
的行，而 `SESSDATA`、`DedeUserID` 这些是 HttpOnly、按名字又排在后面，很容易
整行漏掉，粘进去会变成「有 18 个 cookie 但没有 SESSDATA」，然后一路报登录失败。
Network 里的 `cookie` 请求头是浏览器实际发出去的全量内容，**包含 HttpOnly**，
一次就能拿全。

两种格式 `parse_cookie()` 都认：`cookie: …` 前缀、分号分隔、多行、带引号、
只有值，以及 Network 里「复制为 cURL」的整条命令（会自己从 `-H 'cookie: …'`
里捞出来）。表格复制出来的是 Tab 分隔的多列，也能解析（取每行前两列，表头和
空行跳过），但注意上面那个只复制可见行的坑。

只想给最少的也可以：只在 `config/bilibili_sessdata.txt` 写一个 SESSDATA 值。
`buvid4` 结尾的 `==` 不会被切断。
**不要手动把 `%2C` 解码成逗号**——浏览器存的就是编码形式，服务端会自己解，
还原成逗号反而可能被 Cookie 解析器当成两段。

还想让机器人**自己续期**（登录态还能救时自动换新 cookie），要再补一项
`ac_time_value`——它不在 cookie 里，而在 localStorage：

```
F12 →「控制台 / Console」→ 输入 localStorage.getItem('ac_time_value') → 回车
→ 复制返回的字符串（带引号，别把引号抄进去）
→ 在 config/bilibili_cookie.txt 末尾另起一行写：ac_time_value=那个值
```

缺它不会影响能否用，只是失效后不能自动续，得重新取一次。

配完先跑一次，别等群里发链接才发现没通：

```
python -m qqbot.videosum BV1c5HK6CEPu --frames 0
```

它会打印登录态是否有效、资料来源（`AI 文稿` 才算真通了），不会把 cookie 打出来：

```
SESSDATA：已读到（222 字符），另带 5 个 cookie
登录态：有效
来源：AI 文稿
```

**它到底「看到」了什么**：所谓 AI 文稿，本质是 ASR 把声音转成文字——只有听觉、
没有画面。实测极客湾一期视频的文稿里，「玄界 / 玄剑 / 玄机 / 悬剑」同一个词出现
四种写法，全是同音错字，这就是语音识别的原始输出。所以：

| 视频类型 | 效果 |
|---|---|
| 口播讲解、评测、访谈、直播切片 | ✅ 准，声音里信息密度高 |
| 音乐、纯剪辑、舞蹈、PV | ❌ 没多少语音可转，文稿是空的 |
| 无声演示、PPT 录屏、代码演示 | ❌ 关键信息全在画面上 |
| 图表、参数、现场实拍 | ⚠️ 只听到讲解者说了什么，看不到屏幕上写了什么 |

为了补上画面，`analyze()` 之后还会调一次 `snapshot()` 抓官方快照帧：

```
x/player/videoshot?bvid=&cid=&index=1
  → 一张 10×10 的雪碧图 + 每帧对应的秒数
  → 按网格裁开，均匀取 6 帧（掐掉头尾各 4%）
  → 当作图片和文字一起发给 DeepSeek（多模态）
```

好处是不用下载视频、不用装 ffmpeg，靠 Pillow 裁图就行：单帧 480×270、十来 KB，
六帧加起来还没一张手机照片大。实测画面里的字幕都能读出来（《双人抬棺》截图里的
「我蹲了蹲了」清清楚楚），所以纯音乐、无声视频也评得动。没装 Pillow 就自动退回
只看文稿，不会报错。

几个踩过的坑：

* 请求头必须带浏览器 UA + `Referer: https://www.bilibili.com/video/<bvid>`，
  否则直接 412；
* `w_rid` 要现算（nav 取 img_key/sub_key → 混淆表重排 → md5(参数 + mixin_key)），
  密钥会轮换，所以只缓存 5 分钟；
* 字幕接口不带签名时，风控降级会返回**别的视频**的字幕（社区 2026-08 查明的），
  所以这里一律走签名版 `player/wbi/v2`；
* 短链是 302，先跟到最终地址才拿得到 BV 号；最终地址里没有就翻落地页 HTML，
  只认 `/video/BV…`、`bvid=` 这类明确写法；
* 分享卡片不走正文，链接埋在卡片 JSON 里——`parse_group_event` 会顺手在原始
  事件里捞一个（`Incoming.attached_url`），所以「转发卡片 → 再 @」也认；
* 卡片里一个链接都捞不到时（`Incoming.has_card` 且 `attached_url` 为空），
  下一句「总结」会回一句「复制链接发我」，并在日志里留一段原始事件 JSON
  （`[事件] 空正文且没解析出链接…`），方便回头查是哪种卡片。

超过 `QQCHATBOT_VIDEO_MAX_MINUTES`（默认 60 分钟）直接拒绝，长视频文稿塞进去
既贵又容易被截断。默认流程是「先回一句在看 → 取文稿 → 发评价」，两条消息，
不会撞被动回复 5 条的上限。

### 大图与长数字

**超过 5MB 的图自动走分片上传**（官方直传二进制的硬上限是 5MB，图片软限制 20MB）：

```
upload_prepare（md5 / sha1 / md5_10m）→ 逐片 PUT 预签名 URL
  → 每片 upload_part_finish → 带 upload_id 调 files 合并
```

实测一张 **7.68MB** 的图：分片完成 + 合并 + 发出，全程约 7 秒（`ttl=86400s`）。

**长数字自动千分位**：出群文本里 6 位以上的连续数字每三位加逗号
（`1234567` → `1,234,567`），URL、CQ 码、小数位、版本号整段跳过不动。
这是原插件为了防 QQ 风控做的（长数字串容易被盯上），现在所有发送都统一过一遍。

### 抽卡 / 开箱 / 库存

| 命令 | 规则 |

| `抽卡` | 每天 5 次；概率 稀有45% / 史诗35% / 神话15% / 传奇5%；硬保底：连续 14 抽没神话第 15 抽必出，连续 29 抽没传奇第 30 抽必出 |

| `查看库存` | 画成一张图：始源/限定/传奇/神话 + 附魔书 + 碎片；`查看全部库存` 连稀有/史诗一起列 |

重复卡**不叠加**，按品质折成奶龙碎片（稀有+10 / 史诗+20 / 神话+150 / 传奇+500）；
开箱抽到的始源卡重复了也一样，折成 100-300 奶龙碎片。

**数据存在 `data/card_users_official.json`**（官方版单独一份，键是成员的 `member_openid`）。
第一次启动时会把旧共用文件 `card_users.json` 里**键不是纯数字**的记录（也就是官方版自己
攒的）搬过来，NapCat 那些 QQ 号记录一个都不动。分成两份是因为两个进程各读一遍再整份
写回时，后写的会盖掉先写的。

卡池目录统一放在 **`data/card/`** 下面：`rare_card`、`epic_card`、`myth_card`、
`legend_card`、`box_card`（始源）、`limited_card`（限定），每个目录里 `cards.json`
记「卡名 → 文件名」。

限定卡不在抽卡池里，是活动 / 补偿之类单独发的；**`查看库存` 和 `查看全部库存` 都会列**
（跟在始源后面，紫色「限定」徽章），也不占用「另有 N 种没列出来」的隐藏名额。
`limited_card/cards.json` 里值是 `null` 的条目（只有名字、没图）一样会列出来。

> 当前工作区只拷了 1MB 以下的图，所以有几个卡池条目没跟过来（例如传奇 7 张只有 3 张有图），
> 代码会**跳过没有图文件的卡**，抽卡不会报错。

库存图和签到图一样，**直接用原插件那套渲染器**（`napcat_render/checkin_card.py` 的
`render_inventory_card`）：5 列网格、每张卡带品质徽章、顶部头像卡、底部碎片卡，
和 NapCat 版视觉一致。

**图是临时文件，发完即删**：渲染到**系统临时目录**（`%TEMP%/qqchatbot-render/`），
上传 → 发出去 → 立刻 `unlink`。所以 `data/` 里**没有 `checkin/` 这个目录**，
也不会有任何签到图/库存图残留。

兜底顺序：原版渲染器 → `card_image.py` 的简版（Pillow）→ 纯文字。
简版只在原版渲染失败（缺 Pillow、字体坏了等）时才出现。

### 锻造系统

规则写在 **`config/锻造系统.txt`**，`qqbot/forge.py` 就是照它实现的（改规则请改那个文件）：

| 命令 | 规则 |
| --- | --- |
| `锻造 石剑` / `锻造 铁剑` / `锻造 钻石剑` | 入场费 = 初始价值：50 / 250 / 500 碎片，**完成度一律从 100 起**。碎片不够会明确拒绝；**石剑例外**，付不起也免费开局 |
| `用力砸` / `用力砸N` | 每回合判一次：增加 / 不变 / **锻造失败**。增加倍率：石剑 ×1.2~1.4，铁剑 ×1.3~1.5，钻石剑 ×1.4~1.6；**成功还会回复 3 完成度**。写成 `用力砸5` 就是连砸 5 回合，结果合并成一条消息，中途锻造失败就停 |
| `结束锻造` / `收工` | **砸满 3 回合**才能收工，收益按下面的对数曲线算（四舍五入）发奶龙碎片；两个词完全等价 |

- 概率表按回合 1~5 写死在 `forge.py`（和规则文件一致），第 6 回合起沿用第 5 行；
- **连砸**：`用力砸5` 等于把接下来 5 个回合的「用力砸」一口气发完，中间状态照常结算
  （时运扣次数、保护到账、重构挂起都算），结果**合并成一条消息**，一锤一行：
  `已进行 5 次锻造，现在价值 120，该回合增加 12，完成度 100%。（第 5 回合）`
  中途**锻造失败就停下**（剑崩了当然也停，剩下的回合不再自动砸）；`用力砸 1` 和
  `用力砸` 等价；一次最多连砸 10 下；
- **幸运暴击**：触发「增加」时另判一次，石剑 3% / 铁剑 8% / 钻石剑 12%，
  倍率换成 ×2.0~2.5（不是叠乘）；
- **完成度**：开局 100，上限 100；锻造失败**不降低价值**，只掉随机 **30~50**
  完成度，完成度掉到 0 或以下剑就彻底崩了，这局立刻结束、拿 0 碎片；
- **完成度回复**：锻造成功（砸出「增加」）回复 **3** 完成度，封顶 100——
  砸到 100 时再成功也不会超；
- **锻造保护已取消**：价值再高也没有“首次失败不清零”的保底；
- **下界合金剑**只能靠 `附魔 升格` 换：倍率 ×1.6~1.8、暴击 20%、失败率**恒定 20%**
  （钻石剑是 20%→28%），不能直接用 `锻造 下界合金剑` 买；
- 局内进度**只在内存里**，重启就散；同群每人一局、互不影响；
- 日常词 `用力砸` / `用力砸N` / `收工` / `重构` **没有进行中的局时当闲聊放过**，不会抢答。

**收益曲线**：`收益 = 完成度/100 × 5000 × ln(1 + 价值/5000)`（`qqbot/forge.py`
的 `reward_for`）。完成度是**乘在 log 外面**的等比折扣（50% 完成度就是拿一半）；
价值远小于 5000 时基本还是「价值 × 完成度 / 100」（略低一点），价值超过 5000 之后
每翻 e 倍只多 5000 碎片，回合数再多也不会指数爆炸。几个真实例子：

| 价值 | 完成度 | 收益 |
| --- | --- | --- |
| 462 | 100% | 442 |
| 1,098 | 100% | 993 |
| 4,637 | 4% | 131 |
| 682,494 | 13% | 3,200 |
| 23,653,522 | 100% | 42,310 |

### 附魔系统（s1）

附魔书由 **`开箱` 20% 概率**开出，存在卡账 `books` 字段里、可以累积。锻造中发
`附魔 <书名>` 用一本（`升格` 吃 2 个次数）：

| 书 | 效果 |
| --- | --- |
| `经验修补` | 「增加」或「不变」都回 **+5 完成度**（成功时这 5 点取代基础的 3 点，不是 3+5） |
| `重构` | 下一锤若「增加」**必定暴击**，并且这一锤有 **2 次重掷**机会（重掷发 `重构`） |
| `时运` | 本局暴击率**翻五倍**，触发**两次**暴击后失效 |
| `升格` | 消耗 **2 个次数**，把剑换成**下界合金剑**：倍率 1.6~1.8、暴击 20%、失败率恒定 20% |
| `保护` | **三回合后**获得一次保护：下一次失败不减少完成度；一局只能一次 |
| `掠夺` | 本局「不变」也会涨价值，倍率 **1.2~1.4**（不暴击） |

- **一局最多用 7 个附魔书次数**（`升格` 占 2 个），次数不够/用满会被拒绝、书不扣；
- 下界合金剑只能靠 `升格` 换，不能直接用 `锻造 下界合金剑` 买；
- `保护` 要砸满 3 回合才到账，所以 **砸满 3 回合就收工的局拿不到它**；
- 光说 `附魔`（有局时）列出手里有哪些书和效果；**没局时只提示先开局，不扣书**；
- `附魔 重构` 是“贴书给额度”：下一锤只要「增加」就必暴击，砸完可以发 `重构`
  重掷（最多两次）；认下这一锤（发别的命令）会把没用完的重掷次数作废；
- 书和碎片共用 `data/card_users_official.json`。

### 锻造排行榜

`锻造排行榜` 把**锻造收益最高的十次**渲染成一张图（`napcat_render/checkin_card.py`
的 `render_forge_rank_card`），固定十行：名次 / 收益 / 锻造人 / 时间（精确到分）。
渲染失败时退回**文字版**，排行榜本身不会看不到。

- 每次**成功收工**记一条，记的是这一局的**收益**（对数曲线算出来的那个数，
  四舍五入，跟实际发的碎片一致）；
- 记录里同时存了当时的**锻造价值**和**完成度**，读榜时按**当前**收益公式重算
  `value`——以后改 K 不用手动改榜单；只有 `value` 的老记录沿用存下来的数字；
- 砸碎（完成度归零、拿 0 碎片）不记；
- 新记录要**严格高于**第十名才进榜，同分先到先得；
- 这次 K 改成 5000 之后，`data/forge_rank.json` 里的十条历史记录已经按新公式
  重算过（旧文件备份在 `backup/forge_rank_before_recalc.json`）。
- 记录落盘在 `data/forge_rank.json`，重启不丢；兼容旧 NapCat 版的文件格式
  （`user_id` 是 QQ 号也能读，新记录存 openid）；
- 整个机器人一份榜，不分群。

### 歌词接龙

群里发**以 `~` / `～` 结尾**的任意消息，就当它是一句歌词，机器人只回**下一句**
（同样带 `~`），不套人设、不加任何解释：

```
明天你是否会想起~      → 昨天你写的日记~
```

两条路子，先确定、后模型：

1. **网易云歌词库**（`lyrics_line.lookup_next_line`）：拿这句去搜歌 → 拉完整 LRC →
   在本地找紧接的那一句。命中就是**确定答案**，不会编；实测
   「明天你是否会想起」→ 老狼《同桌的你》→「昨天你写的日记」（约 1 秒）。
2. **模型兜底**：库里没这首歌时才问 DeepSeek，低温度（0.2）、只准回一行，
   它要是回「【不知道】」或者解释性的话，一律丢掉。

两条都失败 → 回「哼，这句歌词我没听过，接不上~」。
命令判定排在**所有命令最前面**（`抽卡~` 会被当歌词，和原插件一致），
机器人自己的消息不算（`author.bot` 过滤），不会自我接龙。

环境变量：`QQCHATBOT_LYRIC=0` 整体关掉、`QQCHATBOT_LYRIC_LIBRARY=0` 只留模型、
`QQCHATBOT_LYRIC_SUFFIX` / `QQCHATBOT_LYRIC_FALLBACK` 改标记与兜底文案。

### 自动复读（+1）

同一个群里，**同一条没被任何规则处理的消息连发两次**，机器人就跟着复读一遍原话
（群友说的“+1”）。命令、关键词、歌词、@AI 命中过的都不跟，避免“@机器人 保存吊图”
连发两次也被复读。

```
群友：这游戏真不行
群友：这游戏真不行
机器人：这游戏真不行
```

- 判定在**所有规则之后**：先跑命令/关键词/歌词/AI，都没命中才看复读；
- 每个群只记上一条（内存，重启清空），上一条是机器人自己的发言不算；
- 只认纯文本；纯图片/表情没有文字，不参与复读；
- **需要能收到群里的全部消息**（`GROUP_MESSAGE_CREATE` / 开放平台里勾「接收全部消息」）。
  只订阅 @ 消息时，机器人看不到别人在聊什么，这条不会触发；
- `QQCHATBOT_REPEAT=0` 关掉。

### 功能列表 / 更新日志

| --- | --- | --- |
| `功能列表` | `config/help.txt` | 功能说明，自己维护；文件不在/为空时回一句兜底 |

切法是字符级无损的、优先在换行处断开。

### 群友画像（长期记忆）

签到图下面那句「他说话什么风格」是靠这个来的：

1. 每条**被 @ 到的消息**进这个人的样本（闲聊不进，和原插件记忆范围一致）；
2. 攒够 `QQCHATBOT_MEMORY_SUMMARIZE_EVERY`（默认 25）条，就在**后台**让 DeepSeek
   总结成 2~3 句画像，落盘到 `data/profiles_official.json`；
3. 之后每次 @ 都把画像塞进系统提示词的「他的说话风格与画像」里；
4. 群里发 `忘掉我` 会连同画像一起清掉。

两次总结之间至少隔 `QQCHATBOT_MEMORY_SUMMARIZE_COOLDOWN`（默认 600 秒），
样本池 `QQCHATBOT_MEMORY_SAMPLES`（默认 40 条）。

实测（把门槛临时调到 4 条）：连续 @ 四句之后日志出现
`[画像] 已更新「一氧化二氢」：…`，第五句回答明显接上了前面的梗。

### 今日猫娘 / 随机老婆

| 命令 | 行为 |
| --- | --- |
| `今日猫娘` | 随机挑一位**见过的**群友，发 markdown 卡片：`# 今日猫娘` + 「这是今日的猫娘 @某某 哦！❤️」+ 一张老婆图 |
| `随机老婆` | 「XXX 今日的老婆是 XX 哦❤️」+ 一张老婆图 |

两个坑都在这里踩过：

1. **@ 必须用 markdown 卡片**。普通文本（`msg_type=0`）里塞 `<qqbot-at-user id="…" />`
   会原样显示成尖括号；改成 `msg_type=2` + `markdown.content` 之后客户端才渲染成蓝色 @。
2. **没有群成员列表接口**（`11253` 无权限），所以名册只收「见过的人」：
   每条群消息都带 `author.member_openid` + `username`，攒进 `data/members_official.json`
   （按群分，节流 5 秒落盘）。刚重启时名册是空的，要等大家说几句话才能抽到人。

## 六、目录结构：config/ 与 data/

按「**会不会变**」分成两个目录，别再混在一起：

```
config/                    ← 静态配置与凭据，写一次就不动（别外传）
  appid.txt                AppID
  secret.txt               AppSecret
  deepseek_api.txt         DeepSeek key（对话 + 联网搜索共用）
  search_api.txt           旧版博查/Tavily 的 key，现在没用到
  bilibili_cookie.txt      B站登录态（整段 Cookie，推荐）
  bilibili_sessdata.txt    B站登录态（只存一个 SESSDATA 的备用写法）
  persona.txt              人设（每次请求都重读，改完立刻生效）
  help.txt                 「功能列表」的正文
  changelog.txt            「更新日志」的正文
  锻造系统.txt              锻造规则说明（写给人看的，代码照它实现）
```

```
data/                      ← 运行时数据，程序自己会写、会变
  card_users_official.json  官方版抽卡记录（openid → 卡/碎片/次数）
  diaotu/            无名吊图
  named_diaotu/      命名吊图 + records.json
  images/            图库：关键词图 + 表情图（2026-10-20 起合并，不再分 faces/）
                      （生成的签到图/库存图不放这里：见下面「临时图」）
  card/              全部卡池（2026-10-20 收进一个目录）
    rare_card/  epic_card/  myth_card/  legend_card/  box_card/  limited_card/
    每个目录里 cards.json 记「卡名 → 文件名」
```

**判断标准**：你会手动编辑它 → `config/`；程序自己写它 → `data/`。

`config_file()`（`qqbot/config.py`）按「`config/` 优先 → `data/` 兜底」查找，所以
**把某个文件挪回 `data/` 也照样能用**，不会因为挪了文件就突然读不到。想整体换位置，
设环境变量 `QQCHATBOT_CONFIG_DIR`。

**`faces/` 已经并入 `images/`**：原先按「表情 / 关键词图」分两个目录，但代码里两者
都是「关键词 → 一个图片文件」，合并后少一层目录、也不会出现「图放错文件夹就不生效」。
`FACE_RULES` / `IMAGE_RULES` 两张表照旧，只是都到 `images/` 里找文件。

所以**两个 bot 可以共用一套图库**（把 `QQCHATBOT_DATA_DIR` 指过去即可）。
但现在已经复制了一份到新工作区，建议先用这份测试，别让测试写入污染正式数据。

> 已知：从原目录只复制了 1MB 以下的小文件，所以 `records.json` 里有 9 个名字对应的
> 大图没跟过来，`发送吊图 <这些名字>` 会回「名为…的吊图文件不存在」，这是预期行为。
> 另外 `wozuohaole.gif` / `wuliangkongchu.gif` 两张关键词图不在 `images/` 里，
> 命中时会打日志「文件不存在」，不会崩。

> **权限坑（2026-10-20 踩过）**：这些目录是上一轮会话复制出来的，**没有继承到写权限**，
> 表现是根目录能写、`data/` 底下一律 `Permission denied`，`保存吊图` 直接失败。
> 解法是让本会话用「完全权限」跑，或修复 `data/`、`tests/` 的权限继承。

## 八、排错

| 现象 | 原因 |
| --- | --- |
| `取 access_token 失败：{'code': 100016 ...}` | AppID / Secret 写错 |
| `取 access_token 失败：{'code': 100007 ...}` | 机器人被封禁/已删除 |
| 启动后日志里一条事件都没有 | 群里没 @ 它；或没开「接收全部消息」 |
| 发图片失败：`{'code': 850019 ...}` | 图片格式不被接受（只认 png/jpg/gif/webp/bmp） |
| 上传图片失败：`... 'code': 10000` | 二进制直传被拒，可能要改分片上传（下一版） |
| 已回满 5 条，改发主动消息 | 同一条消息回太多次；主动消息还受群主开关限制 |
| 日志出现 `[事件] 跳过重复消息` | 正常：平台会重推同一条，已按 `msg_id` 去重 |
| `保存吊图` 回「吊图保存失败」，日志 `[Errno 13] Permission denied` | 工作区子目录**没有写权限**（`data/`、`tests/` 是复制来的，没继承到沙箱许可）。切会话到「完全权限」，或恢复这两个目录的权限继承后正常 |
| 手打「@机器人 什么」没反应 | 手打的不是真 @，正文里是字面量；用 QQ 的 @ 选择器点机器人 |
| 发出去的 @ 显示成 `<qqbot-at-user .../>` 原文 | 普通文本里不会解析 @，必须走 markdown 卡片（`msg_type=2`） |
| @ 别人时机器人也来搭话 | 2026-10-20 修过：原先「见到任何 @ 标记」就当在叫自己。现在启动时从 `/users/@me` 取自己的 `id` / `union_openid`，只认这两个 |
| 「今日猫娘」说群里还没见过人 | 名册只记见过的发言人；等大家说几句话再抽 |
| 启动日志「没配 config/deepseek_api.txt」 | 没配 DeepSeek key，@ 机器人只会走关键词规则 |
| 回复「呜……AI暂时走丢了」 | DeepSeek 调用失败，日志里有 `[AI] 调用失败：...` 的真实原因 |
| 机器人记不住刚才聊的 | 记忆只在内存里，重启就清空；另外只记这个人自己的对话 |
| 说「没看到图片」 | 图是单独一条发的、且超过 120s（或没提「图」）；重发一张再问，或者句子里带上「图」 |
| 日志 `[识图] 下载失败` | CDN 链接取不到（过期/网络），这条当纯文字处理 |
| 问图时卡 60s 后回「AI 走丢」 | 多半是动图/大图让模型超时；换 jpg/png，或调大 `QQCHATBOT_AI_TIMEOUT` |
| 大图报 `850031 上传文件超过大小限制` | 超过 200MB 硬限制；图片软限制 20MB，超了平台会降级成文件类型 |
| 分片报 `40093001 文件上传失败，请重试` | 分片通道偶发异常，重试一次通常就过 |
| 视频总结说「只看到标题和简介」 | 日志区分两种：`没配 SESSDATA` = 文件空着；`SESSDATA 被拒（-101）` = 配了但已作废，重新取一次 |
| 日志说「读到 N 个 cookie 但没有 SESSDATA」 | 从「应用 → Cookie」表格 Ctrl+A 复制的，只带了已渲染的行，HttpOnly 的 SESSDATA 被漏掉。改从「网络 → document 请求 → 请求标头 → cookie」复制值 |
| 没退出登录，cookie 一会儿就失效 | SESSDATA 随浏览器访问滚动刷新，旧值作废（有效期写到 2027 年也没用）。改用整段 Cookie `config/bilibili_cookie.txt`——只给一个 SESSDATA 时缺 `bili_jct` / `ac_time_value`，自动续期也做不了。最省心的做法是用无痕窗口登录取 cookie，取完关掉窗口 |
| `--refresh` 报「续期页面没给 refresh_csrf」 | 服务端没下发 token，通常是这份会话已经彻底作废；只能重新取一次 cookie |
| 某个视频明明有内容，却只有标题 | 视频本身没开 AI 摘要（`data.code=-1`），且没 CC 字幕。看日志确认，不是配置问题 |
| 视频总结说「B站把我拦下来了」 | 412 风控，通常是请求太密或 IP 被盯；等几分钟再试 |
| 视频总结说「链接我没认出来」 | 只认 `bilibili.com/video/BV…`、`b23.tv/…`、`bili2233.cn/…`、`BV…`、`av…`；别的站不支持 |
| 手机分享过来总结不了 | 先看日志有没有 `卡片链接=…`：有就是解析问题（已支持整段分享文案、粘中文、`bili2233.cn`、小程序中转页）；没有就看下一条 |
| 日志里是 `[卡片消息] 小程序 … source: 哔哩哔哩` | 平台把小程序卡片转成了纯文字，里面没有链接。现在会按 `title` 去 B站 搜；日志 `[视频] 按标题搜…最高 0.xx` 就是它在搜。搜不到会让人重发链接 |
| 按标题搜出来的不是同一条 | 同类系列（`①/②/③`）或搬运太多。调低/调高 `QQCHATBOT_VIDEO_TITLE_MATCH`，或直接发链接最稳 |
| 日志出现「空正文且没解析出链接，原始事件（截断）」 | 这种卡片里根本没有 URL。让用户改成「B站 → 分享 → 复制链接」再发；把那段 JSON 留着，可以按新卡片格式再加一条解析 |

## 十、平时怎么跑

| 方式 | 做法 | 说明 |
| --- | --- | --- |
| 双击 | `start-official-bot.bat` | 开一个控制台窗口跑，日志同时追加到 `logs/bot.log`；窗口关掉就停 |
| 开机自启 | `Win+R` → `shell:startup`，把 bat 的**快捷方式**放进去 | 登录后自动开窗口跑 |
| 后台无窗口 | 任务计划程序：触发器「登录时」+ 操作「启动程序」指向 bat | 选「只在用户登录时运行」 |

三条要记住：

1. **同时只能跑一个**：两个进程连同一个机器人会抢事件、并且都整份写 `data/`，后写的盖掉先写的；
2. 停：窗口里 `Ctrl+C`，或者直接关窗口；
3. 想换数据目录/换凭据，改 `data/` 里的文件后重启即可（人设 `persona.txt` 不用重启，每次请求都重读）。

## 十一、防止电脑睡眠

**休眠状态跑不了任何程序**，所以这里做的是「不让电脑睡」，不是「睡了还能跑」。

启动时（`keep_awake()`）会调 Windows 的 `SetThreadExecutionState`：

```
ES_CONTINUOUS | ES_SYSTEM_REQUIRED   ← 系统保持唤醒
（故意不加 ES_DISPLAY_REQUIRED）     ← 屏幕照样可以关，省电
```

进程活着就生效，退出时自动解除（`finally` 里恢复 `ES_CONTINUOUS`）。
标准库 `ctypes` 实现，不装任何东西。启动日志里会有一行：

```
[电源] 已请求阻止系统睡眠（显示器仍可关闭；要关掉设 QQCHATBOT_KEEP_AWAKE=0）
```

关掉：`set QQCHATBOT_KEEP_AWAKE=0`。

### 还是睡了？按这个顺序查

| 场景 | 处理 |
| --- | --- |
| **笔记本合盖** | 合盖会绕过一切软件请求。控制面板 → 电源选项 → 选择关闭盖子的功能 → 接电源/用电池都改成「不采取任何操作」 |
| 现代待机（Modern Standby） | 管理员 PowerShell 跑一次：`powercfg /requestsoverride PROCESS python.exe SYSTEM` |
| 干脆把睡眠关了 | 管理员 PowerShell：`powercfg /change standby-timeout-ac 0`（用电池时把 `-ac` 换 `-dc`） |
| 关机 / 注销 / 断网 | 这些都会让机器人停，软件层无解；要常驻建议放一台不关的小主机或云服务器 |

> 睡眠期间机器人是**离线**的：QQ 会把消息留在服务端，醒来后能补收到一部分，
> 但别指望「睡一觉起来消息一条不落」。

## 附：与原插件的差异

- 原插件 `保存吊图` 没有图时回「没有找到上一张图片」，本版一致；
- `发送吊图 名字` 也是两级回退：先 `named_diaotu`，没有再翻全部卡池（含限定卡），都没有才提示；
- 原插件所有文案经过千分位处理（`textfmt.py`），本版出群文本也统一过一遍（`format_numbers`）；
- 原插件会识别手打的「@机器人名字」，本版只认平台的真 @（`<@openid>`）和
  启动时取到的机器人 username；
- **@ 的语义不同**：原插件 @ 一律走 AI；本版**命令优先**，`@机器人 保存吊图` 仍然存图；
- **锻造 / 附魔 / 排行榜已补上**：规则、概率、附魔效果都照 `config/锻造系统.txt` 和原插件搬；
  排行榜兼容旧 `forge_rank.json`（旧记录是 QQ 号也能读），新记录存 openid；
- **联网搜索已补上**：原插件 @对话 挂 `web_search`，本版也挂了（DeepSeek Search，
  key 与对话共用）；歌词补救轮那套搜索没搬（歌词先查网易云库，查不到问模型）。
- 记忆：短期按人（每人最近 20 条，内存）+ 长期画像（落盘 `data/profiles_official.json`），
  和原插件一致；
- 识图没有「描述里带上 @人」这种附加能力，只做看图说话。
